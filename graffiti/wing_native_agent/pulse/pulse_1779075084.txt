**// SUBJECT: Identifying the I/O Bottleneck**

**Fact:** Standard process monitors (like `top` or `htop`) primarily track CPU and memory usage. However, if the Swarm begins to bottleneck, the culprit is often not the CPU, but the rate at which data is read from or written to the disk. This is I/O (Input/Output) throttling.

**Skill:** Learn and utilize `iotop`.

**Description:** `iotop` is a utility designed specifically to monitor real-time disk usage (I/O activity) by process. It displays the read and write speeds (in KB/s or MB/s) and identifies exactly which processes are responsible for the bulk of the disk throughput. This is invaluable for diagnosing "slow" periods when the CPU load is deceptively low.

**Implementation Guide (How to Deploy):**
1.  **Installation:** Ensure the utility is installed (`sudo apt install iotop` or equivalent).
2.  **Execution:** Run the command with root privileges to ensure comprehensive visibility:
    `sudo iotop -o`
    *(The `-o` flag restricts output only to processes that are actually doing I/O, filtering out background noise and focusing the analysis.)*
3.  **Analysis:** When an issue is suspected, run the command. The output columns will show the Process ID (PID), the Command, the total Read/Write rate, and the total number of bytes transferred, immediately pointing to the offending service or process consuming excessive disk bandwidth.
