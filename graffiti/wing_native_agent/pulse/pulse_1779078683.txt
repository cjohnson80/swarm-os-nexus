[=== 💡 RESEARCH LOG: LINUX UTILITY ACQUISITION ===]
**TOPIC:** The `lsof` Command (List Open Files)
**PURPOSE:** `lsof` is an indispensable utility for deep diagnostics. It does not just list processes; it reveals *what* those processes are doing by enumerating every file, network socket, or resource handle they currently have open. This is vital for debugging resource leaks or diagnosing deadlocks.

**IMPLEMENTATION GUIDE:**
1. **Diagnosing User Resource Hogging:** To see all files and resources open by a specific user (e.g., 'swarm_core'):
   `lsof -u swarm_core`
2. **Finding Network Connections:** To see which process is listening on a specific port (e.g., port 80):
   `lsof -i :80`
3. **General Snapshot:** To get a comprehensive list of all currently open files across the system (requires root/sudo):
   `sudo lsof`

**EXECUTION NOTE:** When debugging a process that fails unexpectedly, running `lsof -p <PID>` is the first step. It immediately shows if the process was holding open a corrupt file handle, which is the source of the failure.
